## 1. Blox-Net — generate, simulate, repair, select
- **Task:** text prompt + a fixed set of cuboid/cylinder blocks → a stacked design that is recognisable and that a real robot can build.
- **Phase I:**
  - GPT-4o writes a feature description, then the role of each block, then each block's pose (x, y, colour, and orientation by swapping dimensions).
  - Each block is dropped in PyBullet. If it moves, the VLM gets the block id, which way it moved and 2 orthographic renders, for up to 2 repair rounds.
  - **Selection:** 10 candidates in parallel → VLM scores each 1–5 → pairwise knockout on "which is more recognisable".
- **Phase II, perturbation redesign:** for each fragile block, sample 8 points on each of 10 rings (1–15 mm) and move the block to the mean of the stable, collision-free samples. Full builds rise from 28% to 96%.
- **Eval:**
  - Recognisability is N-way label ranking by GPT-4o: top-1 63.5% at N=5, 48.5% at N=10, 41.5% at N=20.
  - Real builds: 59/60 trials completed.
- **Limits:** primitives only, the VLM is both designer and judge, no human raters.

## 2. Blocks Assemble! — structured RL
- **Task:** 16 magnetic cuboids, 165 blueprints (141 train / 24 test), 2 grippers in MuJoCo.
- **Observation:** a block graph that does not depend on global position or rotation.
  - Nodes: height, held flag.
  - Edges: relative pose error vs the blueprint, magnet-alignment delta, "should connect" and "is connected" flags.
- **Model:** 3 graph-attention layers. Each block node outputs a key; each gripper query picks a block by dot-product attention (pointer action).
- **Training:** PPO, 1B steps.
- **Reward:** change in a potential: dense alignment, +1 per correct connection, −1 per wrong one, a contact-force penalty.
- **Results:**
  - 99.9% on 2–6 blocks, 89.6% on unseen 12–16-block blueprints.
  - Without attention 4.1%; a flat ResNet gets 0%.
  - Training on one blueprint only gets 0% on the 16-block blueprint; multi-task gets 90.9%.
  - Agents discover sub-assemblies on their own.
- **Lesson:** the representation decides whether it learns at all. Flat features failed completely.

## 3. ORASP — optimal assembly-sequence planning
- **Formulation:** assembly by disassembly. State = a binary vector over connections still present; action = remove one connection. Equivalent sub-assemblies are merged into one graph node.
- **Hard constraints prune branches:**
  - precedence rules;
  - at most 4 loose pieces at once;
  - at most 3 parts per loose piece.
- **ORASP search:** a random sequence gives a cost bound, then depth-first branch-and-bound. Optimal without building the full graph, valid because costs are non-positive.
- **Large assemblies:** a DQN over the connection vector, with a curriculum by connection count.
- **Results:** 6–108 s vs 5,000–20,000 s for the integer-programming baseline (Culbertson). The DQN solves the ISS (32 parts) and JWST (180 parts / 256 connections) in about 35 min.
- **Limits:** no geometry or motion planning (we already have `blocking.ts` for that).

## 4. Speech to Reality — voxel repair
- **Pipeline:** speech → GPT-4 picks the noun → Meshy.ai mesh → voxelize (any cell the mesh touches) → repair loop → UR10 builds it from 40 cuboctahedron voxels.
- **Repair rules:**
  - more than 40 parts → shrink everywhere by one voxel;
  - cantilever longer than 3 → shrink along that axis only;
  - unsupported column taller than 4 → shrink along z.
  - Thresholds came from physical tests. Dropping any one check broke at least one object.
- **Build order:** sort by z, x, y; a part is placed only if it touches the ground or an already placed part.

## 5. Survey — patterns worth taking
- **Eureka:** an LLM writes reward code, training scores it, and a text critique feeds the next round. It beats human-written rewards in most cases.
- **MimicGen:** 200 human demos become 50k+ by recombining segments.
- **Code-as-policies / ProgPrompt:** the plan is a program, checked against a rule base.
- **SayCan / Text2Motion:** a learned value function checks feasibility before each step is committed.
- **Named gap:** generative models ignore gravity and collision. That is the same gap our `bridge` and `capStuds` passes patch.

## 6. DRL grasp+assembly (abstract only)
- **Method:** DQN for grasping and PPO for peg-in-hole. Prior knowledge narrows the action space; constraint rewards score grasp and assembly quality.
- **Results:** 90% grasp success; peg-in-hole at 3 mm tolerance 86.7% in simulation, 73.3% on the real robot.
- **Takeaway:** mask actions with rules first, learn the rest.
